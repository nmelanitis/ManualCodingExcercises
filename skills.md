# Manual Data Science Practice Skill

## Purpose

This project is a hands-on practice space for keeping Python data-science skills
active. The focus is manual coding with NumPy, pandas, scikit-learn, seaborn,
Matplotlib, statsmodels, PyTorch, and Hugging Face—not hiding the important work
behind generated abstractions.

## Learning contract

- Default to guided templates with numbered `TODO` items, short hints, and room
  to type the code manually.
- Do not replace unfinished exercises with full solutions unless a solution is
  explicitly requested.
- When help is requested, start with the smallest useful hint. Explain the idea,
  then show a focused example if needed.
- When reviewing an attempt, identify the first meaningful issue, explain why it
  matters, and let the learner make the correction when practical.
- Prefer a small, working exercise over a large, polished project.

## Template conventions

- Use Python scripts divided into VS Code/Jupyter cells with `# %%`.
- Put configuration such as paths, target names, and random seeds near the top.
- Keep one concept or question per cell.
- Use numbered tasks in execution order and include a concise hint when the API
  is not obvious.
- End each exercise with written observations or reflection prompts.
- Store reusable blank worksheets in `templates/` and personal attempts in the
  matching topic folder under `exercises/`.
- Write generated charts to `outputs/figures/` and tables to `outputs/tables/`.
- Treat `data/raw/` as immutable. Put cleaned or transformed data in
  `data/interim/` or `data/processed/`.

## Optional data inspection with Data Wrangler

- Keep pandas, the Jupyter Interactive Window, and the Data Viewer as the default
  inspection workflow.
- Use the Microsoft Data Wrangler VS Code extension only as an optional visual
  companion when column profiles, distributions, or suspicious values would be
  easier to explore interactively.
- When useful, preview cleaning transformations in Data Wrangler without changing
  the raw dataset.
- Read and understand any pandas code generated by Data Wrangler. For practice
  exercises, retype or adapt the useful operations in the worksheet rather than
  treating generated code as the finished answer.
- If Data Wrangler is used, record its findings in the exercise. Do not accept a
  visual transformation without checking dtypes, row counts, missingness, and
  relevant domain rules in code.

## Coding conventions

- Use descriptive `snake_case` names and explicit intermediate variables while
  learning; concise code is not the primary goal.
- Prefer vectorized NumPy/pandas operations, but compare them with a plain Python
  approach when that teaches the underlying behavior.
- Set random seeds for reproducible examples.
- Label plot axes and titles, and call `plt.tight_layout()` before saving.
- Keep data leakage in mind: make train/test splits before fitting transforms or
  models whenever an exercise moves beyond EDA.
- Add a short interpretation after statistical tests and model metrics; numbers
  without a conclusion do not complete an exercise.

## Suggested progression

1. NumPy arrays, indexing, broadcasting, and vectorization.
2. pandas selection, cleaning, reshaping, grouping, and joins.
3. EDA and visualization with seaborn and Matplotlib.
4. scikit-learn preprocessing, pipelines, validation, and metrics.
5. statsmodels estimation, assumptions, diagnostics, and interpretation.
6. PyTorch tensors, autograd, datasets, training loops, and evaluation.
7. Hugging Face tokenizers, datasets, pretrained models, and fine-tuning.

## Definition of done for an exercise

- Every numbered task has been attempted.
- The file runs from top to bottom with the selected environment.
- Important output has a written interpretation.
- At least one edge case, assumption, or limitation is noted.
- The learner can summarize what was practiced without reading the code.
